<objective>
Change `events.Emit` from a function that swallows every write failure to one that returns
it, and prove the whole shape end-to-end through one real caller: a gate whose event log
cannot be written still reaches its verdict, and the gardener is told on stderr.

This is the phase's tracer slice. It touches every layer the phase modifies — the domain
write path (`internal/events`), a real production call site (`internal/gate`), and the
gardener's channel (stderr) — on one thin path, with a runnable end-to-end verification.
The remaining eight call sites (plan 02), durability (plan 03) and the health surface
(plans 04-05) expand outward from it.

Purpose: SUB-01 is the phase's gate. Until a caller can tell a written event from a dropped
one, a stale log cannot be told apart from a failing one and every downstream measurement in
this milestone is untrustworthy.

Output: `Emit(e Event) error`, two gate closures that report-and-continue, and two tests —
one at the package boundary, one end-to-end through a real gate run.

## Planner decisions (no CONTEXT.md exists for this phase)

The phase was planned from research and requirements only. Every decision below was made
here, states its reasoning, and follows the option RESEARCH.md recommends unless noted.

1. **Disposition at every call site is report-and-continue, never propagate.** Success
   criterion 4 forbids an unwritable log turning a successful gate into a failed one. The
   exact idiom is the one already shipped at `internal/cli/soil.go:recordDraw`.
2. **The stderr notice keeps the event name**: `hugel: event %q not recorded: %v`.
   `01-PATTERNS.md` offers the plain `recordDraw` wording or the named form; a gate emits up
   to eight events per run, so a notice that does not say which one was lost is not
   actionable. RESEARCH.md's own sketch uses the named form.
3. **No de-duplication of the stderr notice.** A gate against a broken log prints one line
   per lost event (up to ~10). Honest per-failure reporting beats a counter; the failure
   marker (plan 04) is the retrospective summary.
4. **`f.Sync()` is not part of this plan.** Plan 03 owns durability, so the tracer stays
   thin and the two changes land as separately revertable commits.
5. **The four direct `events.Emit` calls in `internal/gate/run.go` (lines 105, 134, 189,
   225) are left untouched here.** Go permits discarding a call's return value, so they
   compile unchanged; plan 02 sweeps them.

## Flagged assumptions (edge probe: unresolved)

The spec-less edge probe classified all three phase requirements as `unclassified`, so all
three stay **unresolved** and are surfaced here rather than silently resolved. SUB-01's:

- **SUB-01 — unresolved.** The edge the requirement implies is *the boundary where the
  failure report itself cannot be delivered*. This plan assumes stderr is always available
  and writable; if stderr is closed, redirected to a full device, or nobody is watching the
  pane, the failure is unreported and hugel does not attempt a third channel. Plan 04's
  failure marker is the second, independent line of defence for exactly this case, and it
  too can be unavailable — see plan 04's assumption.
- **SUB-01 — unresolved (concurrency).** `hugel dispatch` runs tenders concurrently. Two
  goroutines emitting into a broken log produce two interleaved stderr notices. Assumed
  acceptable; no serialisation of the notice is planned.
