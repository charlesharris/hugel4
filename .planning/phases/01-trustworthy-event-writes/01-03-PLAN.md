## Planner decisions

1. **`Timer.Done` gets the error return too** (RESEARCH.md Open Question 1, recommendation
   accepted). It has zero production callers today and simply forwards to `Emit`; phase 2
   widens emission across every subsystem and is the phase most likely to reach for it.
   Leaving `Done` silent now would bake in the exact inconsistency phase 2 inherits.
2. **`Sync` is a plain checked statement, never deferred and never discarded.** A deferred
   call cannot influence the return value, so `Emit` could report success on data that never
   reached the file. The `Close` call stays deferred: once `Sync` has succeeded the data is
   durable, and a later close failure does not undo that.
3. **No directory-entry fsync.** Making a newly created file's *directory entry* durable
   needs a second fsync on the parent directory handle and a way to know that this call was
   the one that created the file. `events.jsonl` is created once in the life of a garden and
   appended to forever after, at roughly five events a day; the crash window this would close
   is the instant between creation and first data sync. Documented as an accepted gap.
4. **No `F_FULLFSYNC` on macOS.** Go's `File.Sync` issues `fsync(2)`, which on Darwin does
   not flush the drive's own write cache (golang/go#26650). Closing that needs an
   OS-specific build-tagged path through `golang.org/x/sys/unix` — a new dependency for a
   single-user CLI writing five lines a day. `Sync` returning nil is the strongest guarantee
   Go's standard library exposes, and the phase claims exactly that and no more.
5. **No performance gate.** An fsync costs low single-digit milliseconds on local SSD
   storage against ~5 events/day. There is no benchmark to write and none is planned.
6. **The doc sweep is part of this plan, not a follow-up.** Four places still describe the
   old contract: Emit's own comment (plan 01), `internal/config/sandbox.go`,
   `internal/events/events_test.go`, and `README.md`. The last three land here.

## Flagged assumptions (edge probe: unresolved)

The spec-less edge probe classified all three phase requirements as `unclassified`, so all
three stay **unresolved**. SUB-02's:

- **SUB-02 — unresolved.** The edge the requirement implies is *where "durable" stops being
  true*. Assumed and not tested: on macOS a successful `Sync` does not survive a power loss
  that empties the drive cache; a crash in the instant between `events.jsonl` being created
  and its first data sync can lose the directory entry on Linux; and a `Sync` that fails is
  covered only by the error path, because a failing fsync cannot be provoked portably in
  `go test` on either target platform. The automated test proves the weaker, testable claim
  — that nothing of ours is buffering — and the source assertions prove the `Sync` call is
  present and checked. This is the honest ceiling and the plan does not claim past it.

## Prohibition recall (spec-less fallback, §B)

Kept from the SUB-02 recall pass, authored descriptor-less in `must_haves.prohibitions`:

- *"Durability must never be claimed beyond what the running platform actually provides."*
  This is the prohibition a durability feature is most likely to violate silently: the code
  is correct, the comment overstates it, and a later reader trusts the comment.

Dropped as routine engineering: must-not-buffer, must-not-hold-a-long-lived-handle,
must-not-lose-earlier-events, must-not-slow-the-caller.
