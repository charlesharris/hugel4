## Planner decisions

1. **The marker is `$HUGEL_HOME/events.failing-since`, a zero-byte file whose mtime is the
   whole payload** — the idiom `internal/cli/compost.go:compostMark` already uses for "when
   did composting last run". A timestamp in a file is one syscall to read and touching it is
   the entire write.
2. **It is created with `O_CREATE|O_EXCL`, not `O_CREATE` alone.** This is the one place the
   codebase's existing marker idiom must be inverted: `markComposted` wants most-recent-write
   wins, and this wants *first*-failure wins. `O_EXCL` failing with an exists error is not an
   error here, it is the answer "already in a failing streak, leave the time alone". The same
   exclusive-create call already appears at `internal/cli/dispatch.go:202`.
3. **Only the four failure paths inside the locked write section mark** — the directory
   create, the open, the write and the sync. A marshal failure means a bad event, not a
   broken log, and a `Path()` failure means the garden's location is unknown, so there is
   nowhere to put a marker. Marking on either would make health report a filesystem problem
   that does not exist.
4. **`clearFailing` runs on every success, unconditionally.** One `os.Remove` whose
   not-exist error is ignored, at ~5 events/day. Stat-then-remove would be two syscalls to
   save one.
5. **`type Health` + `func HealthOf() (Health, error)`.** RESEARCH.md Open Question 2
   recommends `events.Health()` returning a `Health` — which will not compile, a function and
   a type cannot share a name in one package. `01-PATTERNS.md` already sketches the resolution
   and this plan takes it: the type keeps the good name, the reader is `HealthOf`.
6. **`LastWrite` and `FailingSince` are both `*time.Time`, nil when the fact does not
   exist.** RESEARCH.md sketched `LastWrite` as a plain `time.Time`; a zero `time.Time`
   marshals to a date in the year 1, which reads as a wrong answer rather than as "never".
   Nil is the honest encoding of a fact that does not exist, and it makes the two fields
   symmetric.
7. **`Health` carries `Reachable` and `Home`.** This is the chicken-and-egg case the phase
   brief calls load-bearing: a log that cannot be written cannot record its own failure, so
   under a wholly inaccessible garden there is no marker *and* no log, and the naive reading
   of those two absences is "healthy, nothing has run" — the exact wrong answer. `Reachable`
   is established from the garden directory itself, and `Home` names the path so the report
   can say where it looked.
8. **`HealthOf` returns an error only when the garden's location cannot be resolved at all.**
   An unreachable garden is an *answer*, not a failure; `hugel yield --health` must be able to
   print it and exit 0.

## The two seams this plan tests with

Both are portable across macOS and Linux and both still fail when the suite runs as root,
unlike a permission-bit trick which root bypasses. The second one is new in this plan and is
what makes the marker testable at all.

- **Total failure — the garden is unreachable.** `HUGEL_HOME` resolves through a regular
  file (join `unwritable` onto `t.TempDir()` and write a byte there). `os.MkdirAll` fails with
  ENOTDIR, so `Emit` fails *and the marker cannot be written either*. Verified this session:
  `os.Stat` on that home succeeds but reports a non-directory, which is how `HealthOf` detects
  it.
- **Partial failure — the garden is fine, the log is not.** `HUGEL_HOME` is an ordinary
  `t.TempDir()`, but `events.jsonl` is created as a *directory*. `os.MkdirAll` on the garden
  succeeds, `os.OpenFile` on the log fails with "is a directory", and the marker *can* be
  written beside it. Verified this session, including that a second exclusive create returns
  an exists error — which is the pin mechanism.

## Flagged assumptions (edge probe: unresolved)

The spec-less edge probe classified all three phase requirements as `unclassified`, so all
three stay **unresolved**. SUB-03's:

- **SUB-03 — unresolved.** The edge the requirement implies is the *boundary between the two
  states it must distinguish*. Assumed: filesystem mtime granularity (one second on most
  filesystems) is enough to date a failure streak that a gardener reasons about in days; a
  streak that starts and is repaired between two health checks is reported as healthy with an
  older last-write, and nothing records that it happened; and under a wholly unreachable
  garden the marker is absent for the same reason the log is, so health reports that it
  cannot answer rather than guessing. The stderr notice at the time of the command is the only
  channel that survives that case — the two mechanisms are independent lines of defence, and
  neither stands in for the other.

## Prohibition recall (spec-less fallback, §B)

Kept from the SUB-03 recall pass, authored descriptor-less in `must_haves.prohibitions`:

- *"The health surface must never report a state it cannot establish."* A health check that
  answers "healthy" from two absent files is worse than no health check, because it converts
  a gardener's suspicion into false confidence.

Canon-referral breadcrumb (surfaced, not minted): *"the marker and the health report must not
disclose the garden's contents"* — file-permission and log-disclosure canon; carried as threat
`T-01-03` and covered by `/gsd-secure-phase`.

Dropped as routine engineering: must-not-reset-the-mtime (a correctness edge, covered by the
pin test), must-not-leak-a-file-handle, must-not-fail-when-the-marker-is-absent.
