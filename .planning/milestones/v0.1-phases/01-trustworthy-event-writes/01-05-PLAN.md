## Planner decisions

1. **`hugel yield --health`, not a new top-level command** (RESEARCH.md Open Question 2,
   recommendation accepted). `yield` already carries four boolean-flag views in one file that
   already imports `events`. The logic stays in `internal/events` so a resident garden in
   phase 5 can reuse it without going through the CLI.
2. **`--health` dispatches immediately after flag parsing, before any transcript is read.**
   Every other `yield` view is built from `~/.claude/projects` transcripts, and `runYield`
   returns early with "no sessions with recorded usage" when it finds none. Health does not
   read transcripts at all, so a late dispatch would make the answer depend on a directory
   that has nothing to do with the question — and would silently answer nothing on a machine
   with no transcripts. `--since`, `--bed`, `--limit` and `--root` are therefore not
   applicable to this view.
3. **`--health` exits 0 whenever it can produce a report, including an unhealthy one.** It
   reports; it does not fail. The only error it returns is the one `HealthOf` returns when the
   garden's location cannot be resolved at all.
4. **Timestamps render as `2006-01-02 15:04` with the codebase's `short` duration helper for
   the "ago" suffix.** SUB-03 is phrased in dates ("since 2026-09-01"), and `yield`'s other
   views use a month-day format that cannot express a year — which is exactly the ambiguity
   this view has to avoid. `short` is already in package `cli` (`internal/cli/tender.go:270`).
5. **`internal/complete/spec.go` must be updated in the same task as the flag.** Discovered
   during planning and named in no source artifact: `internal/complete/spec_test.go` parses
   the flag registrations in `internal/cli` and fails the build when the completion table and
   the CLI disagree. Registering `--health` without its completion entry turns
   `go test ./...` red. This is not optional and not a follow-up.
6. **Package `cli` gets a `TestMain` before it gets its first test.** It has none today
   because it has no tests. `internal/gate/main_test.go` and `internal/tender/main_test.go`
   record why this matters: the test that leaked into the gardener's real log was the one
   that never thought about the garden. Adding the guard with the first test is cheaper than
   adding it after the second one leaks.
